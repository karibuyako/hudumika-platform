# HUDumika Error Codes

Every error response carries a stable `code`, a human `message`, and `requestId`.

## Format

```json
{
  "code": "ORDER_NOT_CANCELLABLE",
  "message": "Order can no longer be cancelled",
  "requestId": "3f2b..."
}
```

Clients switch on `code`, never on `message` text.

## Global

| Code | HTTP | Meaning |
| --- | --- | --- |
| `VALIDATION_FAILED` | 422 | Request body failed validation (with `errors[]`) |
| `UNAUTHORIZED` | 401 | Missing, expired, or invalid credentials |
| `FORBIDDEN` | 403 | Authenticated but lacking permission |
| `NOT_FOUND` | 404 | Resource missing or not visible to caller |
| `CONFLICT` | 409 | State transition not allowed |
| `RATE_LIMITED` | 429 | Too many requests (Retry-After header) |
| `INTERNAL_ERROR` | 500 | Unexpected failure (details never leaked) |
| `NOT_IMPLEMENTED` | 501 | Contract path exists but is not implemented yet |

## Conventions

- Codes are stable strings; adding is allowed, repurposing is not.
- `INTERNAL_ERROR` never includes stack traces or provider internals.
- 404 is used for resources that exist but are not visible to the caller
  (no existence leaks).
